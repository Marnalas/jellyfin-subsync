Subsync

Configure the connection to the ffsubsync sidecar and how your library paths map onto the sidecar's. What gets synced comes from your Jellyfin libraries - the sweep only sees external subtitles Jellyfin has already indexed, so run a library scan after adding new ones.

Base URL of the subsync-sidecar service, e.g. http://subsync-sidecar:8000 (use the docker compose service name so it resolves on the internal network).
Pick which of your Jellyfin libraries the sweep syncs subtitles for, and tell it where each library's folders live from the subsync-sidecar container's point of view. The Jellyfin-side paths below come straight from each library's own configuration - you only need to fill in the sidecar-side equivalent. Libraries are disabled by default.

This is path translation only - it does not choose what gets swept, your Jellyfin libraries do. But every enabled library's folders still need a sidecar path filled in here: a subtitle whose path matches no mapping is skipped with a warning, because the sidecar would have no way to reach it.
Comma-separated, no dots, e.g. srt,ass,ssa,vtt,sub. ffsubsync reads and writes each of these formats natively, so non-SRT subtitles are synced (and kept) in their original format rather than being converted to SRT. This narrows what Jellyfin already recognises as a subtitle (ass, mks, sami, smi, srt, ssa, sub, sup, vtt) - adding anything outside that set here has no effect.
How long a single sync may spend running on the sidecar.
How long a submitted job may sit queued on the sidecar before this plugin gives up and cancels it. Reaching this means more work is being submitted than the sidecar has workers for - compare "Max parallel jobs" below with the sidecar's MAX_PARALLEL_JOBS. Set to 0 to wait indefinitely.
Timeout for one individual HTTP call to the sidecar (submitting, polling, cancelling), not for the sync itself. Rarely needs changing.
How many subtitle files the sweep submits to the sidecar at once. Default is 1. Raising this only helps if the subsync-sidecar container's own MAX_PARALLEL_JOBS environment variable is also raised - the sidecar itself defaults to (CPU cores - 1) worker threads, but if you leave this plugin setting at 1, only one file is ever in flight regardless of how many the sidecar could run. Conversely, raising this past the sidecar's actual worker count just queues extra jobs there without speeding anything up. Set both together, sized to the sidecar container's available CPU.

The sweep's schedule (default: daily at 02:00) is edited separately, from Dashboard > Scheduled Tasks > "Sync unsynced subtitles" > Edit - same place as any other Jellyfin task.
